Start with plain fetch + HTML parse (Cheerio) for static pages; use a headless browser (Puppeteer) only when the page is JS-rendered or gated by client-side logic. That’s the standard tradeoff: cheaper/faster first, browser only when needed. 
Rate limiting
Use a token bucket / leaky bucket limiter and add retries with jittered backoff. Keep per-domain quotas so one site can’t starve others. (This is the canonical pattern.) 
Caching strategy
Product/site facts (APRs, program pages): cache with ETag/Last-Modified revalidation and a TTL (e.g., 30–180d depending on volatility).
User-specific recommendations: don’t cache globally; at most short per-user cache (minutes) to avoid stale advice. 
Fallback handling
Wrap external calls with a circuit breaker + timeouts. On failure: serve last cached fact (with “as-of” date) or a graceful “not available” note—don’t guess. 
User data integration
Compose: user RPC snapshot → (optional) web fact → answer. Never merge raw scraped HTML into prompts; store tiny, cited metrics (value + as_of) and join them with the user’s numbers at render time. (Faster, auditable.)

Entity extraction
